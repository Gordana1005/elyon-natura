# Elyon — врска со Сигма (инсталација во канцеларијата)

**Што е ова:** мала програма што на секои 15 минути **само чита** од Сигма (базата `SSBNatura` на серверот
`192.168.7.22`) и ги праќа магацинските документи до CRM-от (Магацин → Движења). Така новата стока што се внесува
во Сигма (прием од погон, набавка, продажба на продавници, извоз, отпис) се гледа во CRM речиси во живо.

- **Никогаш не запишува во Сигма.** SQL корисникот `elyon_reader` има право само да чита и само наведените колони.
- **Само излезна врска (HTTPS 443).** Ништо во канцеларијата не се отвора кон интернет.
- **Без лични податоци:** се праќаат шифри и количини на артикли, датуми, објекти (04 / 08 / 11 / Лабораторија),
  корисничкото име на операторот во Сигма и името на фирмата-клиент. Адреси, телефони, контакт-лица, белешки и
  имиња на физички лица **не се читаат воопшто**.
- **Секоја пратка е потпишана** (HMAC) со таен клуч, па CRM-от прифаќа само од оваа програма.

Распоред:

| Задача | Кога | Што прави |
|---|---|---|
| `Sigma delta` | секои 15 мин, 06:00–22:00 | документите сменети од последното праќање + отворените нацрти |
| `Sigma nightly` | секоја ноќ во 03:30 | целосна проверка на документите од последните 120 дена (избришаните во Сигма се означуваат), артиклите и состојбите со набавните цени |

> Ако Сигма-СБ потврди дека нивните ноќни задачи (бекап) работат околу 03:30, преместете ја ноќната задача на
> 05:00 — програмата само чита, но нема потреба да ја оптоварува базата во исто време.

---

## Чекор 1 — SQL корисник само за читање (го прави Сигма-СБ)

На компјутерот каде е оваа папка, извршете:

```
node connector.mjs --print-grants
```

Тоа го печати точниот SQL. Испратете го на Сигма-СБ со барањето:

> „Ве молиме креирајте SQL логин `elyon_reader` на `SSBNatura` со право **само SELECT** на колоните во прилогот (и
> ништо друго: без INSERT / UPDATE / DELETE / EXECUTE, без други табели). Ни треба TCP/IP пристап на порта 1433 од
> компјутерот `<име на компјутерот>` во канцеларијата. Лозинката испратете ја одделно.“

Колоните што се читаат (сè друго останува затворено):

| Табела | Зошто |
|---|---|
| `InventoryHead`, `InventoryLine` | книжените магацински документи (прием, пренос, производство, продажба, извоз, отпис) |
| `WorkDocInHead`, `WorkDocInLine` | кој и кога го креирал документот; отворените нацрти („најавено“) |
| `DocType` | видот на документот (влез / излез / пренос) |
| `Item` | шифра, име, класа, единица мерка, група (бренд) на артиклот |
| `StockObject` | состојба по магацин и набавна цена (CalcBuyPrice) |
| `Client` | само шифра и име на фирмата-клиент |

## Чекор 2 — инсталација

1. Компјутер во канцеларијата што е **секогаш вклучен** (Windows 10/11 или Windows Server), со точно време
   (Windows Time / NTP — потписот важи само ±5 минути).
2. Инсталирајте **Node.js 20 LTS** или понов (https://nodejs.org → „LTS“, стандардна инсталација).
3. Копирајте ја папката `tools\sigma-connector` во `C:\Elyon\sigma-connector`.
4. Отворете **PowerShell како администратор** и извршете:

   ```
   cd C:\Elyon\sigma-connector
   npm install --omit=dev
   ```

## Чекор 3 — тајните (никогаш во датотека)

Во PowerShell како администратор (вредностите ги добивате од сопственикот на CRM; не ги праќајте по е-пошта):

```
[Environment]::SetEnvironmentVariable('SIGMA_SQL_PASSWORD', '<лозинка од Сигма-СБ>', 'Machine')
[Environment]::SetEnvironmentVariable('SIGMA_CONNECTOR_SECRET', '<таен клуч од CRM>', 'Machine')
```

Потоа одјавете се и најавете се повторно (или рестартирајте), за да ги види програмата.

## Чекор 4 — поставки

Копирајте `config.example.json` во `config.json`. Обично не треба да се менува ништо; проверете:

- `sql.server` = `192.168.7.22` (или името на серверот), `sql.database` = `SSBNatura`, `sql.user` = `elyon_reader`;
- `endpoint` = адресата на CRM (`…oufoazmnbwugtfldkwsn…/stock/sigma/ingest`) — **само македонскиот CRM**;
  програмата одбива адреса на бугарскиот систем;
- `opening` = `2026-09-22` (пописот — документите пред него не се праќаат).

## Чекор 5 — проба

```
node connector.mjs --mode delta --dry --out proba-delta.json
node connector.mjs --mode nightly --dry --out proba
```

`--dry` ништо не праќа: само ги чита документите и ги запишува во датотеката. Отворете ја `proba-delta.json` и
проверете дека има документи (`docs`) и дека **нема** адреси, телефони и имиња на лица.

Првото вистинско праќање (го прави целосната проверка):

```
node connector.mjs --mode nightly
node connector.mjs --mode delta
```

Ако одговорот е **„disabled“** — во CRM уште не е вклучено примањето од Сигма (Магацин → Поставки, сопственикот).
Ништо не е запишано и ништо не се губи: следното праќање ќе ги испрати истите документи.

## Чекор 6 — автоматско извршување (Task Scheduler)

PowerShell како администратор:

```
schtasks /Create /TN "Elyon\Sigma delta" /TR "\"C:\Program Files\nodejs\node.exe\" \"C:\Elyon\sigma-connector\connector.mjs\" --mode delta" /SC DAILY /ST 06:00 /RI 15 /DU 16:00 /RU SYSTEM /F
schtasks /Create /TN "Elyon\Sigma nightly" /TR "\"C:\Program Files\nodejs\node.exe\" \"C:\Elyon\sigma-connector\connector.mjs\" --mode nightly" /SC DAILY /ST 03:30 /RU SYSTEM /F
```

- `/RI 15 /DU 16:00` = на секои 15 минути, 16 часа од 06:00 (до 22:00).
- `/RU SYSTEM` = работи и кога никој не е најавен.
- Проверка: Task Scheduler → Task Scheduler Library → Elyon → „Last Run Result“ = `0x0` значи успешно.

(Истото може и рачно во Task Scheduler: Create Task → „Run whether user is logged on or not“ → Triggers: Daily
06:00, „Repeat task every 15 minutes for a duration of 16 hours“ → Actions: Start a program `node.exe` со аргументи
`C:\Elyon\sigma-connector\connector.mjs --mode delta`.)

## Логови и проблеми

- Логови: `C:\Elyon\sigma-connector\logs\connector-ГГГГ-ММ-ДД.log` (секое извршување, колку документи, одговорот).
- `state.json` го памети времето на последната промена во Сигма. Ако го избришете, следното `delta` праќа сè од
  22.09 (безбедно: CRM-от ги препознава веќе примените документи).
- Програмата завршува со код 1 кога нешто не успеало; следното извршување ги испраќа истите документи повторно.

| Порака во логот | Што значи / што да се направи |
|---|---|
| `Login failed for user 'elyon_reader'` | погрешна лозинка (SIGMA_SQL_PASSWORD) или логинот не е креиран |
| `The SELECT permission was denied` | Сигма-СБ не ги дала сите колони од Чекор 1 |
| `ESOCKET` / `Failed to connect` | серверот 192.168.7.22 не е достапен или портата 1433 е затворена |
| `HTTP 401` | погрешен SIGMA_CONNECTOR_SECRET или погрешно време на компјутерот (проверете го часовникот) |
| `disabled` | во CRM не е вклучено примањето од Сигма (сопственикот) |
| `fetch failed` / `ENOTFOUND` | нема интернет или е блокиран HTTPS кон `*.supabase.co` |

## Ажурирање

Заменете ги датотеките во `C:\Elyon\sigma-connector` со новите, **без** `config.json`, `state.json` и `logs`, па
извршете `npm install --omit=dev`. Задачите во Task Scheduler не треба да се менуваат.

## Безбедност накусо

- Корисникот во Сигма гледа само колоните од Чекор 1 и не може ништо да промени.
- Врската е само излезна, преку HTTPS, со потпис (HMAC-SHA256) и време (±5 мин), па стара или туѓа пратка се одбива.
- Тајните се во Windows променливи, не во датотеки.
- Истите полиња ги праќа и рачниот CSV извоз (`docs/stock/build_sigma_stock.py`) — списокот е во `sigma-fields.json`.

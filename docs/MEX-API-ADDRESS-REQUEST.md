# MEX Поштa — барање до поддршка: адреса на примачот во JSON API

Статус: ЧЕКА ИСПРАЌАЊЕ (Миле). Подготвено 2026-08-11.

Зошто: порталот на MEX ги прикажува целосните адреси на пратките, но JSON API
(`list_shipments.php`, `get_shipment_status.php`) не го враќа полето
`receiver_address` — проверено во живо на 2026-08-11 со нашиот клуч. Адресите ни
требаат за да ги пополниме профилите на клиентите во CRM-от и за автоматска
синхронизација на испораките. `add_shipment.php` веќе го прима полето, значи го
чуваат — треба само да го изложат во одговорите.

До: (адресата за поддршка од договорот/порталот на MEX)
Предмет: Барање за дополнување на JSON API — адреса на примачот во одговорите

---

Почитувани,

Ние сме корисници на вашиот JSON API (сметка „BIO NATURAL") и го користиме за
интеграција со нашиот CRM систем.

Забележавме дека одговорите на `list_shipments.php` и `get_shipment_status.php`
ги содржат полињата `receiver_name`, `receiver_city`, `receiver_phone`, `cod` и
статусите, но **не и адресата на примачот** (`receiver_address`), иако таа се
внесува при креирање на пратката преку `add_shipment.php` и е видлива во вашиот
веб-портал.

Ве молиме, дали е можно да се додадат следниве полиња во одговорите на
`list_shipments.php` и `get_shipment_status.php`:

1. **`receiver_address`** — улица и број на примачот (како што е внесена при
   креирање на пратката);
2. по можност и **`receiver_city_id`** — ID на градот/зоната од `get_cities.php`.

Ова би ни овозможило целосна автоматска синхронизација на испораките во нашиот
систем, без рачно преземање податоци од порталот.

Дополнително прашање: постои ли во порталот опција за извоз (Excel/CSV) на
листата пратки со сите колони, вклучително и адресата? Тоа би ни помогнало како
привремено решение додека полето се додаде во API.

## Белешки за нас (не се испраќа)

- API клучот е во `docs/VAULT.md` §6 (`MEX_API_KEY`) — никогаш во пораката.
- Проверено во живо 2026-08-11: `list_shipments.php` враќа
  `tracking_id, sender_reference, current_status_id/_name, receiver_name,
  receiver_city, receiver_phone, cod, created_at, last_update_at` — без адреса;
  `get_shipment_status.php` враќа уште помалку. Непостоечки endpoints → 404.
- Сметката има 3.171 пратки во последните 30 дена; постари се достапни со
  `created_from` (default прозорецот е само филтер, не граница).
- Ако MEX го додаде полето: `scripts/import-mex-shipments.mjs` (кога ќе се
  напише) може да се префрли од CSV на API и да оди на cron — спарување по
  телефон (последни 8 цифри) + `cod` + датум.
- Ако MEX одбие, а извоз постои: Миле симнува CSV/Excel од порталот
  периодично и го пуштаме низ истата скрипта.
